# 类脑社区 AI API 网关

面向 Discord 社区的 AI API 网关：**用 Discord 身份做门禁，用全站共享的小时级 token 额度做计量**，请求最终转发到自建的 Bifrost 上游。

它不训练模型、不做路由、不管上游密钥——只回答两个问题：**谁有资格用**、**全站每小时能用多少**。

```
社区成员 → 本网关（门禁 + 额度） → Bifrost（OpenAI 兼容） → 各 provider
```

## 特性

| 能力 | 说明 |
|---|---|
| **Discord 门禁** | OAuth2 授权码流程，校验是否为指定服务器成员；身份组可选收紧，留空即"是成员就放行" |
| **两个额度池** | MiniMax 池 30M tokens/小时、GLM 池 3M tokens/小时，**全站共享**；按模型名自动分池 |
| **免费模型** | 非 minimax / glm 的模型（如本地 qwen3-embedding、reranker）不计量、不占额度 |
| **滚动窗口** | 从该池首次计入开始计时，1 小时后归零，不是整点重置；填 0 表示不限 |
| **全站限流** | 每分钟请求数硬闸（默认 30），防止单个客户端把上游打爆 |
| **令牌管理** | 每个成员自助创建多把 key，可限制额度、过期时间、模型白名单、来源 IP |
| **用量审计** | 每次请求的模型、token 数、耗时全部落库 |
| **单二进制** | Go 编译产物内嵌前端，运行时只需一个容器、一个 SQLite 文件 |
| **双架构** | 发布包同时包含 `linux/amd64` 与 `linux/arm64`，安装时自动选择 |

## 快速开始

**部署方**（需要 Docker）：

```bash
tar -xzf community-gateway-YYYYMMDD.tar.gz
cd community-gateway-YYYYMMDD
bash deploy.sh          # 6 步向导
```

向导会依次收集 Discord 应用凭证、服务器 ID、站点地址、管理员账号、上游地址与密钥，然后自动建库、起容器、写配置、建渠道。

**使用者**：

1. 打开站点，点「使用 Discord 继续」
2. **My plan** 页看两个额度池的剩余量
3. `API Keys` 页创建密钥（**只显示一次**）
4. 用 `https://<域名>/v1` 作为 Base URL 调用

## 设计取舍

**为什么用 Docker 而不是直接跑二进制**
运行时镜像基于 `debian:bookworm-slim`，只 `COPY` 一个预编译二进制，不含 Go 和 Node。部署方不需要装任何编译环境。

**为什么默认只绑 `127.0.0.1`**
网关本身不做 TLS。它必须藏在 Cloudflare Tunnel / Caddy / nginx 后面，由那一层终止 TLS。直接暴露 3000 端口意味着会话 Cookie 明文传输。

**为什么额度从"首次消费"开始计时**
固定整点窗口会让"晚上 8 点才开始用的人"只享受 2 小时就重置，体验割裂。滚动窗口对每次使用公平，代价是重置时间不固定。

**为什么额度是全站共享而不是按人分**
按人分会出现"一百个人各占一份、谁也用不满"的浪费，也会让总量不可控。全站共享把上限直接对齐上游的真实配额：无论来多少人，一小时最多就这么多 token。代价是一个人刷爆，所有人一起等重置——所以配套了每分钟限流和使用规范。

**为什么非 minimax / glm 的模型免费**
本地 AI MAX 上的 qwen3-embedding / reranker 跑的是社区自己的电，不花上游一分钱。把它们计入共享池只会让 RAG 场景寸步难行。按模型名判断归属，新加本地模型不用改配置。

**为什么 SQLite 要开 WAL + 连接池上限**
SQLite 是单写者模型。默认连接池会开到上千，并发写必然撞 `database is locked`。本项目改为 `journal_mode=WAL` + `busy_timeout=10s` + 连接池上限 8，中小社区足够；并发再高应换 MySQL / PostgreSQL。

## 使用规范

本站是社区公益资源，不是公共 API 服务：

1. **密钥必须按「软件 + 用途」命名**，如 `cherry-studio-个人笔记问答`；看不出用途的 key 会被删除
2. **禁止任何形式的商业化使用**：出售/转售/出租 API 或额度、接入商业平台或付费项目、作为第三方盈利服务的一部分调用、账号共享 / 代用 / 一人多号

完整措辞与后果见 [使用说明书 1.3](docs/使用说明书.md#13-使用规范必读)。

## 安全须知

- `.env`、`.deploy-config`、`preset.local.env` 含密钥，**已被 `.gitignore` 忽略**
- 发布包默认不含任何密钥，只带占位符；`--with-config` 才会把本机配置打进去（仅限内部迁移）
- 上游密钥只存在于网关数据库，不下发给普通成员
- 备份文件包含所有 key 与用量，需加密存放
